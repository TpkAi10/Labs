## 2. analysis.py

### validate_todos(data)

Проверяет:
- корень — список,
- каждая запись — словарь,
- `id`, `userId` — положительные целые, `id` уникален,
- `title` — непустая строка,
- `completed` — логическое.

Для строгой проверки используется `type(value) is int` и `type(value) is bool`:
`True` проходит `isinstance(x, int)`, но не является подходящим `id`.
При нарушении — `ValueError` с пояснением.

### completion_counts(todos)

Словарь `userId → число завершённых задач` для всех пользователей,
включая тех, у кого 0 завершённых.

### top_users(counts)

Отсортированный список `userId` с максимумом завершённых.
Пустой словарь или максимум 0 → `[]`.

### leader_tasks(todos, leaders)

Завершённые задачи лидеров, исходный порядок.

### select_tasks(todos, user_id, parameter=None) — вариант 14

Незавершённые задачи пользователя с длиной `title >= parameter`.
Параметр — целое неотрицательное число. Порядок сохраняется.
Неизвестный пользователь → `[]`. Исходные записи не изменяются.

### Проверки

| Вызов | Ожидание |
|---|---|
| `completion_counts(sample)` | `{5: 2, 10: 2}` |
| `top_users({5: 2, 10: 2})` | `[5, 10]` |
| `leader_tasks(sample, [5, 10])` → id | `[1, 3, 4, 5]` |
| `top_users({})` | `[]` |
| `top_users({5: 0})` | `[]` |
| `select_tasks(sample, 5, 5)` → id | `[2]` |
| `select_tasks(sample, 5, 6)` | `[]` |
| `select_tasks(sample, 999, 0)` | `[]` |
| `select_tasks(sample, 10, 100)` | `[]` |

## 3. main.py

### Обработка ошибок

- `FileNotFoundError` — файла нет.
- `UnicodeError` — не UTF-8.
- `json.JSONDecodeError` — **раньше** `ValueError`, потому что это его подкласс.
- `ValueError` от `validate_todos` — структура.
- `OSError` — доступ к файлу.

При ошибке входных данных **не перезаписывает** прежние результаты.

### Пример работы

    Количество завершённых по пользователям:
      пользователь 5: 2
      пользователь 10: 2
    Лидеры: [5, 10]
    Задачи лидеров сохранены: leaders.json
    Введите user_id: 5
    Минимальная длина названия: 5
    Подходящих задач: 1
      id=2 title=Циклы
    Выборка сохранена: selected.json

## 4. fetch_profile.py

### Разбор кода

- **Адрес** `https://api.github.com/users/<login>` — ресурс API GitHub,
  отдающий профиль пользователя. Логин подставляется через `quote`,
  чтобы специальные символы не сломали URL.
- **GET** — метод чтения ресурса. Не меняет данные на сервере.
- **Таймаут** `timeout=10` — ограничивает ожидание ответа 10 секундами,
  чтобы программа не зависла при проблемах с сетью.
- **Заголовки**:
  - `Accept: application/vnd.github+json` — просим JSON,
  - `User-Agent` — GitHub требует его, иначе вернёт 403.

### Обработчики ошибок

- `HTTPError` — сервер вернул статус: 404 (не найден), 403 (доступ),
  429 (слишком много запросов).
- `URLError`, `TimeoutError`, `socket.timeout` — сетевые проблемы.
- `ValueError`, `UnicodeError` — данные не похожи на профиль или не UTF-8.
- `OSError` — доступ к файлу.

### Если сети нет

Создан `profile_sample.json`:

    {"login": "demo", "id": 1, "name": null}

Прочитан через `json.load`, выведен логин `demo`. Использованы учебные
локальные данные — это равноценный режим выполнения упражнения.
