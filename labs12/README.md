# Итоговый проект. План мероприятий (вариант 14)

## Вариант
14 — План мероприятий.  
`amount` — количество участников.  
`completed` — мероприятие проведено.

## Назначение
Консольная программа для учёта мероприятий: просмотр, добавление, поиск,
изменение статуса, удаление, статистика. Данные хранятся в `data.json` (UTF-8).

## Формат данных
Файл `data.json` — JSON-массив объектов:

    [
      {"id": 1, "title": "Лекция по Python", "category": "учёба", "amount": 40, "completed": false},
      {"id": 2, "title": "Хакатон", "category": "соревнование", "amount": 60, "completed": true}
    ]

Правила:
- `id` — положительное целое, уникальное.
- `title`, `category` — непустые строки после `strip()`.
- `amount` — целое >= 0, логические не принимаются.
- `completed` — строго `bool`.
- Корень — список, каждая запись — словарь.
- Все пять ключей обязательны, дополнительные ключи допустимы.
- Новый `id` = max + 1, для пустого — 1.

## Пример данных и ожидаемая статистика

    [
      {"id": 1, "title": "Лекция по Python", "category": "учёба", "amount": 40, "completed": false},
      {"id": 2, "title": "Хакатон", "category": "соревнование", "amount": 60, "completed": true},
      {"id": 3, "title": "Круглый стол", "category": "учёба", "amount": 15, "completed": true},
      {"id": 4, "title": "Олимпиада", "category": "соревнование", "amount": 25, "completed": false},
      {"id": 5, "title": "Экскурсия", "category": "досуг", "amount": 30, "completed": false}
    ]

Ожидаемая статистика вручную:
- Всего: 5
- Выполнено: 2
- Не выполнено: 3
- Сумма участников: 170
- По категориям:
  - досуг: 30
  - соревнование: 85
  - учёба: 55

## Результаты сценариев приёмки

| Сценарий | Ожидание | Факт |
|---|---|---|
| Файла нет | Пустой список, меню доступно | совпало |
| JSON `[]` | Пусто, статистика нули | совпало |
| Добавлены 4 и 2, вторая завершена | Всего 2, выполнена 1, невыполнена 1, сумма 6 | совпало |
| Название `  Python  ` | Сохранено `Python` | совпало |
| Поиск `PY` при `Python` | Найдено | совпало |
| Пустое название, `amount=-1`, `amount=abc` | Повторный ввод, лишней записи нет | совпало |
| Изменение статуса неизвестного ID | Сообщение, данные не изменены | совпало |
| Удаление отменено | Запись сохранена | совпало |
| Удалена id=1 из [1, 2] | Осталась id=2; новая получит id=3 | совпало |
| Сохранение и перезапуск | Все поля восстановлены | совпало |
| Повреждённый JSON или повторный ID | Запуск прекращён, файл не изменён | совпало |
| Ошибка сохранения | Нет сообщения об успехе, можно продолжить | совпало |

## Как работает путь записи

1. Пользователь вводит название, категорию, количество в меню.
2. `add_record` обрезает пробелы, проверяет непустоту, создаёт запись с `next_id`.
3. Запись добавляется в список.
4. При сохранении `save_records` пишет список в `data.json` (UTF-8, отступ 2).
5. При следующем запуске `load_records` читает файл, `validate_records` проверяет структуру.
6. Запись снова доступна в меню.
